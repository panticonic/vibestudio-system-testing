# Application entry capture

Each task binds a public Natlang function and actual arguments from the installed semantic library. The domain function returns its own typed value. Nested functions and installed skill mounts retain their normal hierarchy. The harness records the declared entry, exact result and all captured calls.

| Stage | Representation | Reason |
| --- | --- | --- |
| Interpret the application request | Public natural-language function | Domain judgment belongs to the application codebase. |
| Select a task's declared entry and bind initial arguments | TypeScript registry lookup | The authored task already names the application contract. |
| Execute with scoped services and capture exchanges | TypeScript runtime plumbing | Call identity and recorded model exchanges must stay exact. |
| Verify effects and requested returned values | Independent application verifier | Observable outcomes determine success. |
| Convert an application result for an existing domain verifier | Temporary TypeScript bridge | Existing verifiers receive their historical fixture envelope while models return only typed application values. The bridge has no model call and changes no value. |
| Retain outcome dimensions and trace | TypeScript attestation | The training exporter must distinguish effect evidence, application return checks and execution conventions. |

Required answers stay required. Effects and returned values are declared separately, and a convention can be omitted only when a specific task contract supplies an independent observable proof of every requested outcome. A name resembling a report is insufficient reason to omit it.

## Reviewed execution conventions (2026-11-22)

The following exact event-count predicates were removed after reviewing the enclosing checks. The complete effect journals remain in evidence; method/argument bindings, real readback, final state and protected-neighbor checks remain required. None of these tasks requests a number of tool invocations.

Repeated reads of an already observed immutable frontier now return the owned cached value in image candidates, chat continuity, editorial workspace/PDF attestation, provider handoff, specialist run, news evidence, launch state, dictation and portfolio. Repeated index queries no longer consume a one-shot capability. Foreign identities remain refused; new effects still require current authority and version checks.

This table documents reviewed mechanisms; the default strict contract for another verifier is not evidence that every check in it has been semantically reviewed. Required answers remain required.

The outcome-workspace answer task now consumes `WorkspaceAnswer` directly, with required current source path, observed revision and verbatim supporting quotation. The two mutation variants judge independent file effects and preservation; their optional revision receipt is recorded separately. PDF-to-vault recovery accepts extra stale retries while preserving the independently observed concurrent addition and a real successful changed-basis write. PDF text/layout/render reads cache repeated exact requests; page coverage remains required, and repeated probes or overlapping page reads do not invalidate correct evidence. Board-migration and incident selection require the correct real observation rather than one read; closeout receipt reads are idempotent per nominated receipt.

## Additional domain review

- Content archive, extension dossier, installed package, panel source migration, System release, webhook admission and workspace share now compare exact evidence membership, allowing any observation order and repeated observations. Foreign or missing required evidence still fails. System release reads any assigned case in any order, caches repeats and canonicalizes its independently stored dossier.
- Asset-integrity recovery locates the changed-basis refusal and real stored receipt among actual attempts; exact final copied bytes, modes, manifest and protected working inventory remain required. Coordinated revision locates the real conflict and authorized atomic application by observed head and exact destination set; editorial and local-presentation checks likewise use real changed/written outcomes rather than attempt positions.
- Panel recovery checks owned native generation, valid observed renderer frames and the requested final state, with protected companions and heads. It does not require the fixture's reference sequence of intermediate actions.
- Read-only discovery/inspection and immutable receipt reads replay in content archive, System release, installed package, workspace share, same-turn evaluation, activation, PTY continuity, CLI identity, personal welcome and workspace assembly. Operator reads serialize concurrent requests and replay baseline/verification receipts while refusing foreign receipts. Mutations retain current authority, identity and version guards.

Two apparent route flags were deliberately retained after reading their task definitions. Browser multi-action goals explicitly request first/then/before ordering (`open-goal-browser-worlds.ts` dispatch goal; expansion worlds ceramics, accessible-tour allocation and tablet return); that order is a requested effect. Publication's `journal.length` counts the oracle's independently enumerated journal-bearing target set, not model calls. Standalone low-level fixture programs with an explicitly tested fixed algorithm remain separate from open application task admission.

The further interference review removed any requirement that a controlled concurrent edit produce a failed model attempt. Independent coedit state, a fresh accepted basis and protected final bytes establish the requested outcome. PDF-vault reads may inspect/follow an owned document without an approved write handoff; revisions still require the exact attested PDF authority. Notification lifecycle evidence locates actual before/after-refresh snapshots among all observations and compares required method/argument evidence as a set, instead of indexing a scripted journal.
