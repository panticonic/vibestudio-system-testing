# triageFailure: decomposition

`triageFailure(failure): { class, evidence }` says which layer a failed system test points at: `infrastructure`,
`documentation`, `harness` or `validator` (the classification the system-testing skill asks for in step 5 of its repair loop). It
reads the record of one test (the packet `systemTests.inspect(runnerTargetId, runId, testName)` returns). It repairs nothing.

| Part                            | Form                                                                | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Read the packet                 | crisp: `triageFailure/signals.ts`                                   | The record has typed fields (failure phase, validation failure, tool failures with `failureKind` and `classification`, cleanup, latency, fixture, orchestration). Reading them is exact. Every signal is bounded to 300 characters and redacted (home paths, tokens, long hex) because a run artifact can hold credentials. At most 10 signals.                                                                                                                                                                                                                                      |
| Layers the typed fields decide  | crisp: `triageFailure/classify.ts`, in rule order                   | The validator threw (`validationFailure`, phase `validation`); the test's own machinery failed (fixture, device-driver or test-authority phase, a fixture scope error, scenario orchestration evidence); the agent misused the platform (`classification` argument-rejection, domain-rejection or guest-code-failure, `failureKind` user-code); the platform failed (`failureKind` infrastructure, cleanup failures, latency violations, unfinished invocations, a session error or other phase). These are discriminants the harness already records, so reading them is mechanism. |
| Decide when no typed field does | its own function, `deliveredOutcome` (`readout: decision`, boolean) | The residue is the semantic case: no failure of any kind, only a validator complaint. Either the agent did the job and the check was too narrow about wording (validator), or the agent did not do part of it (documentation). One question over two strings, which is what the executor can answer.                                                                                                                                                                                                                                                                                 |
| Quote the evidence              | crisp: `evidence.ts`                                                | The evidence is the record's own fields, so extraction is a table: per class, which signal sources decide it, in order; three signals at most.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Whole run                       | crisp: `run.ts`                                                     | Reads the run's packet with the `systemTests` service and triages each failed test from its per-test record.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## What measurement changed

The first design asked the executor for all four layers at once from the signal list (`classifyFailure`, one 4-way decision with an ordered rule list). On LFM3 Q8_0 it scored 0.50 on validation and 0.42 on train, defaulting to `infrastructure` even for a validator that threw (a typed `validator-error` signal). A discriminant the record carries is not a judgment, so those rules moved into `classify.ts` and the model keeps the one question that is.

The existing `likelyIssue` heuristic in `diagnostics.ts` stays a signal (`heuristic`) among the others; it names a failure shape, not a repair layer.

## Measurement

No recorded run exists on the authoring machine (`~/.config/vibestudio/system-test-runs` is absent), so `cases.jsonl` holds
packets built in the exact `FailureDiagnostic` shape from the defect stories of the repository's own fix history (a peer
cancelling an Iroh stream, a device driver that never settled an approval wait, a validator that rejected "thirty seconds" for
"30s", and the like). Replace or extend them with retained packets when runs exist; a retained packet must have home paths and
credentials removed first. Each class has stories in every split. Gate: class accuracy of at least 0.85 on validation and on the locked test split. Only 5 of the 28 records reach the model (`MEANING_ONLY` in `classify.test.ts`); the typed rules are tested exactly.
