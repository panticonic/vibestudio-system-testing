# Program-run native authority and goal meaning (pre-edit inventory)

All 17 literal program-run worlds were read before this change. They ask actual execution/output, conditional approved recovery, source freshness, inspection-only checks, or conditional signatures. One explicitly authorizes exactly one call; another forbids an alternate sample after rejection; stale refresh is explicit in only the refreshing world. None imposes a universal two-attempt ceiling, one receipt read, zero inspections of other owned active candidates, or exact return-list length as an application protocol.

The common producer is SST open-goal-program-run-managed.ts, consumed by web-brief-managed.ts registration/qualification and authored-teacher.ts. Base skills/open-program-run supplies the single typed native catalog/run/read/sign API and its exact TS boundaries. Base open-user-goal/workOnProgramRunGoal.nl composes this hierarchy; runtime-evidence-review interprets supplied evidence. The Host observed-content admission must register program-run with observations[catalog,inspections,attempts,observations], artifacts[signedText]. This is application protocol, shared across native Core loaders; no compiler/model engine implementation changes or SDK regeneration are needed.

Native run currently enforces actual active project, public sample grant, current inspected callable/source revision, original JSON input, no concurrent mutation, initial versus actual rejection/interruption continuation and allowed stale refresh. These are retained. Existing max2 is independent of those grants and blocks a second approved recovery after two actual rejections. Receipt reads are currently artificially one-shot, preventing a new read of the same retained output's current status/authority. Inspection uses only the globally newest inspection rather than a matching issued project/revision, causing an unrelated permitted read to invalidate an earlier exact current observation.

Admission also grades world.expected attempt count/order/value and expected.next, forced target-only inspection, unconditional expected source movement, and expected signature presence. Private reference trajectories can remain in qualification, but cannot define the only correct user trajectory. Native independently retained input/output/source/receipt/signature facts remain crisp; mandatory native-bound meaning review judges requested program/sample selection, exact-once or no-retry restrictions, requested output/inspection and conditional signature. No new runs/observations are fabricated and no existing capture is rewritten.

## Implemented boundary and validation

Native admission now permits individually approved distinct initial samples and arbitrarily many actually justified recovery steps; it retains same-input refresh restrictions and actual initial/rejection/interruption conditions. It selects a matching issued project/revision inspection, then independently checks current native source before invoking. Retained receipts can be reread; each actual read is preserved with its then-current source verification and signing authority. The verifier binds every actual retained input/output and every provided public receipt, preserves actual source/authority changes rather than demanding a private expected change, and validates an actual signed envelope against retained native attempt plus real ECDSA verification. Corrupted signed bytes are rejected before parsing against the authentic native digest.

The private reference remains usable by qualify, but its attempt count/order, target-only read route, next-step label and required signature presence no longer grade alternate programs. Mandatory native-bound goal review now judges the requested effects/findings against actual catalog, issued inspections, captured attempts, readbacks and signed bytes. No requested question or exact-once restriction is waived by a native grounding pass.
