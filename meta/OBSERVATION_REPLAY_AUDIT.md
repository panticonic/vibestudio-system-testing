## Mechanism inventory and changes

This review covers all eight template roots, including Examples and legacy scoped fixtures outside the open-goal verifier files. The initial broad search found 426 candidates; the focused numeric observation-cardinality/one-shot search found 191. Candidates include comments, native protocol/data cardinalities and actual defects; these numbers are search inventory, not counts of defects or evidence of completed semantic review. Source-cited focused expressions are recorded in `skills/system-testing/observation-check-inventory.json`.

* **Issued observation membership, not invocation cardinality.** `semantic-evidence.ts` joins exact native values and distinguishes required evidence coverage from the count/order of reads. Tendril accepts a genuine current projection regardless of other probes; retention accepts any issued matching projection and still independently checks the current native revision.
* **Read coverage and actual effects are separate.** News and image original/readback collections use exact member coverage. PDF raster/layout evidence joins by page identity, preserving the reading order *within* the actual document layout. Client diagnostics accepts repeated/reordered independent observations while keeping exact requested mutation order/count, final native state and genuine issued return values. A second readonly inspection no longer invalidates an unchanged issued client basis; native generation/revision/CAS checks remain mandatory. Program callable inspections require genuine owned evidence rather than a scripted inspection count. Owned preview rereads remain bound to the submitted native receipt, with unchanged upload/submit effects.
* **Legacy scoped observation wrappers.** Architecture, agentic-change, Android inventory/readiness, delivery history and panel inspection, extension source/runtime, Gmail history/projection/launch evidence, template candidate/review, problem draft, build profiling receipts, publication package reads and tour opening state no longer reject additional readonly observations. Existing protected final state, native payload, identity and required returned answers are checked. Pair/install/confirm/write/send/restart counts are unchanged.
* **No one-shot readonly service gates.** VCS delivery, PDF layout, Git Bridge review, native suite plan, cleanup receipts, local-delivery readback, skill confirmation/readback, onboarding, assigned web research and immutable replay checkpoint ports permit repeated assigned reads. Snapshot-producing onboarding/research/remote continuation operations share an inflight immutable read. Replay keeps the canonical checkpoint timeline independent of inspection order. Skill confirmation reuses its original issued decision receipt rather than reinjecting the controlled coedit.
* **Owned immutable coordinates can be revisited.** VCS history accepts any assigned coordinate and reuses its stable receipt. Explicitly ordered user tasks retain ordered first visits; repeats do not advance that sequence. Memory recall no longer prescribes one search/source alternation per revision. Owned revision reads retain exact committed file/path/hash checks, and verification still requires genuine recalled leads and native source evidence for claimed citations. Unknown queries/revisions and forged claims fail.
* **Shared Base ports.** `skills/capabilities/workflow.ts` preflights any assigned operation, including concurrent/repeated calls. Unknown operations never dispatch. `skills/pdf-intake-bindings/index.ts` accepts authorized page subsets within the assigned batch budget; the required native probe is performed internally. Native encryption/engine/page availability, extraction-mode authority and exact digest/page receipts remain checked. Calls share inflight results; a failed read cannot poison unrelated future explicit reads. No automatic retry is introduced. The additional Base binding review is documented by its owning change.
* **Other template owners.** Personal removes one-shot GitHub diagnosis/setup/route/repository and Mission card reads. Spectrolite shares its native document snapshot and permits verified handoff evidence rereads. News shares its original native observation. Examples, System and Google carry their own `OBSERVATION_REPLAY_DECOMPOSITION.md` and candidate inventories, covering snapshot replay, native client inspection and Google cursor/version/provider/readback scopes.

## Deliberately retained constraints

Distinct captured frontier counts in `open-goal-{dictation,image-candidate,news-evidence,regency,specialist,editorial}-managed.ts` count memoized native states, not caller reads: their read ports return an existing final state after those transitions. Specialist artifact reads, Testkit closeout reads, PDF layout maps, PTY observations and development audit maps are keyed native evidence coverage; repeats do not add entries. These constraints continue to require both requested sides of a comparison.

`packages/natlang-services/src/ownedOperationsOracle.ts` checks audit snapshots created by the native cleanup verifier, not teacher-requested read invocations. `web-brief-managed.ts` pairs independently verified cache bytes with each captured fetch receipt; their cardinality is generated evidence alignment. Result finding counts, distinct selected resource counts, page fragments, recipients, source-file sets, final filesystem contents and native CAS/authority boundaries remain application invariants. Denied-scope zero effects and exactly authorized mutations retain their original checks. Protocol tests that deliberately exercise one fixed operation or a fixed small function remain unit tests rather than corpus admission routes. The teacher capture's single-root check binds one actual authored invocation and does not constrain its child tree.

The focused tests accept repeats, independent read order, concurrent immutable reads, and real PDF native extraction. They reject foreign IDs/slots/queries/pages, stale revisions, unauthorized modes, digest mismatches, forged citations/findings, missing required evidence, extra mutations and reversed requested mutation order. No paid model calls or campaign source mutation are part of this review.

Authored teacher execution failure is also separate from capture corruption: the capture now retains `rootOutcome`, marks a non-done root as `executionError`, and keeps `trainingEligible` false. Available records remain retained. Only missing/invalid lineage, model identity and actual record transport/cursor defects enter `captureErrors`; failed skill completion or a violated requested dependency is an execution outcome. The generated capture-code regression executes the actual producer with complete failed-root records and separately checks wrong teacher identity remains a capture error.
