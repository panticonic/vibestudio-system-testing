# Native mutation receipt replay

Mechanism inventory: completed native mutation receipts were treated as single-use RPC responses. A caller losing a response could not retrieve the actual committed result. This differs from executing a second mutation.

- `workers/notification-state-fixture/index.ts`: refresh now retains its exact original request/result in SQLite, coalesces identical in-flight requests and returns that receipt on exact retry. Foreign IDs, labels and generations fail. Audit exposes the actual committed refresh count, which the outcome verifier requires to be one. All notification worlds are exercised with a second native transport attempt.
- `open-goal-workspace-share-managed.ts`: exact request replay rechecks owned current observation, scope decision, workspace heads, untouched fixtures and retained bytes. It returns the prior native receipt without another write or another actual-effect journal entry. A test invokes the real prepared service and verifies the whole outcome after retry, plus changed request/session/retained-byte negatives.
- `open-goal-source-attribution-managed.ts`: exact assignment/state/conclusion replay rechecks current native workspace state, original scoped evidence and retained artifact bytes. The same native original receipt is returned; incorrect evidence and foreign requests remain rejected. Its reusable exact receipt helper is tested for caller failure after commit, concurrency and changed content/authority. Full native VCS preparation of this domain was not rerun by this bounded test suite.
- Base `skills/scratch-handoff-bindings/index.ts`: shared private-artifact writer now retrieves an identical body's receipt after rechecking actual UTF8 bytes, coalesces concurrent identical requests and allows retry after an uncommitted I/O failure. Changed/corrupted bytes never cause an overwrite. Real-filesystem tests verify one artifact and source preservation. All existing consumers inherit this storage behavior, while their domain authority checks remain separate.
- Base model contracts distinguish one actual transition/artifact from repeated receipt retrieval. Notification instructions no longer require exactly one refresh RPC.

`MUTATION_RECEIPT_REPLAY_INVENTORY.json` retains source-bound sibling guard candidates for semantic review. It does not claim that every predicate is a defect or that every mutation API has been qualified. Other one-shot outer domain guards can still prevent their own retries; the generic shared-writer improvement alone is not proof those wrappers are complete. Existing explicit authoring/provenance-history/reconciliation receipt paths already have their own native replay behavior and should retain authority rechecks.
